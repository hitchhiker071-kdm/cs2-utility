# 最终计划：CS2 道具本

> 由 grill-with-docs 审问收敛后产出。决策依据见 `docs/adr/`，术语见 `docs/glossary.md`。

## 一句话目标

把散落在 B 站视频中的 CS2 道具教学（往往只有十几秒）摘录成**字段化 + 动图 + 可搜索**的道具本，电脑/手机都能随时查。

## 工作流（每一条道具的录入路径）

1. 用户看 B 站视频，发现要摘录的道具
2. 用户提供：**视频链接 + 时间戳 + 分类（地图/点位/道具类型）+ 用途/效果**
3. Reasonix：下载视频 → 截取片段 → 转码动图 → 录入数据 → 部署更新
4. 用户验收条目（动图清晰、字段正确）

## 阶段划分

| 阶段 | 内容 | 完成标志 |
|---|---|---|
| 0 工具链 | 安装 ffmpeg + yt-dlp | 两个工具可用 |
| 1 MVP（Dust II） | 搭建网页骨架 + 数据模型，录入 2~3 条真实道具，部署 GitHub Pages | 电脑浏览器可打开；手机通过网址可访问；动图自动播放 |
| 2 Dust II 填满 | 持续投递录入，直至该图条目齐备 | Dust II 条目覆盖常用点位 |
| 3~8 铺开 | 按顺序逐图录入：Mirage → Inferno → Ancient → Cache → Anubis → Nuke | 各图条目齐备 |

## 验收清单（对每个阶段的产出）

- [ ] 电脑浏览器双击/本地打开可浏览
- [ ] 手机通过 GitHub Pages 网址可访问（无需电脑开机）
- [ ] 单条道具字段完整：点位命名、投掷方式、瞄准点文字、效果、来源+时间戳
- [ ] 动图自动播放且清晰可辨（站位/瞄准点可见），单条体积 ≤ 1~2MB
- [ ] 树状浏览（地图→点位→道具类型）与全局搜索可用
- [ ] 新增条目流程顺畅：用户给"链接+时间戳+分类+用途"即可入库
- [ ] 页面不含个人信息（账号/昵称）

## 边界（非目标）

- 不做饰品库存/价格/行情
- 不做第三方 API 自动拉数据
- 不做多人协作/社区

## 风险与对策

| 风险 | 对策 |
|---|---|
| 公开页面遭遇版权投诉 | 非商用 + 注明来源，风险极低；最坏情况仓库下架，本地文件无损，可重部署 |
| 动图制作成本高、节奏慢 | 脚本化流水线；MVP 先验证 2~3 条再铺开 |
| B 站视频失效 | 摘录即保值，动图入库后不再依赖源视频 |
| 字段结构后期变动 | MVP 阶段定稿字段，铺开前冻结 |
