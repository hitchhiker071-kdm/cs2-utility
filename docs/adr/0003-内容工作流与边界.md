# ADR-0003：内容工作流与项目边界——人工摘录流水线

- 状态：已接受
- 日期：2026-07-29
- 背景：用户从 B 站看道具教学视频，需要把散落的十几秒片段摘录进道具本。

## 决策

1. 内容采用**人工摘录流水线**，不做第三方 API 自动拉数据：
   - 用户在 B 站观看视频，发现要摘录的道具
   - 用户提供：视频链接 + 时间戳 + 分类（地图/点位/道具类型）+ 用途描述
   - Reasonix 负责：下载视频 → 截取片段 → 转码动图 → 录入数据文件 → 部署更新
2. 明确**非目标**（划清边界，避免过度设计）：
   - ❌ 不做饰品库存/价格/行情（那是另一类应用领域）
   - ❌ 不做第三方 API 自动拉数据（API 数据不含"瞄准点"这类教学信息）
   - ❌ 不做多人协作/分享社区
3. 条目类型预留扩展位：除道具（烟/闪/火/雷）外，**战术类条目**（配合、套路）后续可同结构录入。

## 理由

- 教学信息的核心（站位、瞄准点、投掷方式）只能从视频中人工提取，API 无法提供。
- 用户是唯一内容决策者（"我来告诉你放哪里"），工具只负责执行。
- 明确非目标可避免把项目做成"CS2 全功能平台"。

## 后果与代价

- 内容产出速度取决于用户看视频与投递条目的节奏。
- 流水线各环节需脚本化（下载→截取→转码→更新数据），否则每条条目重复手工操作成本高。
