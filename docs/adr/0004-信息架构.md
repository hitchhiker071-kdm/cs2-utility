# ADR-0004：信息架构——条目字段、浏览方式、覆盖顺序

- 状态：已接受
- 日期：2026-07-29
- 背景：道具本需要一致的条目结构、好用的浏览与搜索，以及明确的覆盖路线。

## 决策

1. **条目字段**（最小集合，可扩展）：
   - 地图
   - 点位 + 道具类型（命名如"投向 A1 的烟雾弹" → 简称"**A1 烟**"）
   - 投掷方式（跳投 / 跑投 / 蹲投）
   - 瞄准点描述（纯文字，用于快速复习）
   - 效果（封住哪、闪到哪）
   - 来源视频 + 时间戳
   - 动图（WebP/MP4）
   - 备注（是否亲测有效、注意事项）
2. **浏览方式**：地图 → 点位 → 道具类型，树状浏览 + 全局搜索（如搜"跳投 烟"）。
3. **覆盖顺序**（每张图做完再做下一张）：
   Dust II → Mirage → Inferno → Ancient → Cache → Anubis → Nuke
4. **分阶段验收**：
   - **MVP（第一阶段）**：Dust II 走通整条流水线，产出 2~3 条真实道具条目，电脑/手机可访问。
   - **长期**：七张图按顺序逐张填满。

## 理由

- 点位命名法"位置 + 道具类型"与玩家社区习惯一致，检索直觉。
- 树状浏览匹配"赛前复习按图查"场景；搜索匹配"忘了某个投法"场景。
- 先跑通一条流水线再铺开，避免内容量压垮未验证的流程。

## 后果与代价

- 字段结构一旦被多条内容填充，调整成本上升——MVP 阶段就要定稿字段。
- 七张图全部完成是长期内容任务（预计每图 20~40 条，总计 150~280 条），需持续投递与录入。
